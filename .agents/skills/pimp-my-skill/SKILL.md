# PIMP MY SKILL

## P1 — Establish scope and GM capability

Read [the preserved request](../../../docs/skills/ORIGINAL-REQUEST.md), [adaptation ledger](../../../docs/skills/AUDIT.md), and [anchor graph](../../../docs/skills/ANCHORS.md). Adding these Markdown sources does not itself authorize executing every maintenance branch, changing another repository, deleting notes, or rewriting attribution. Higher-priority instructions and actual tool permissions remain authoritative.

GM refers to the user-identified SolutionsAsService/gm-mcp project, not “game master.” Inspect current task scope, repository instructions, working-tree changes, tool inventory, and available GM/MCP connection dynamically. Prefer GM for all operations it actually supports, including child tasks. Make a harmless read-only capability probe using the discovered schema. Never invent a GM tool name, claim a connection without a successful probe, or interpret absence of a skill named GM as proof that a GM server is absent. Installation alone is not proof of model-visible tool exposure.

If GM is unavailable or unsuitable, record GM_UNAVAILABLE or GM_DEGRADED plus evidence and missing capability. Apply the user's invariant-4 manual fallback for authorized work using available tools. Do not use grep/find as substitute search tools; use permitted directory, file, or structured query APIs. If those cannot do the work, report the blocker. Pass the same capability result/fallback constraints to children.

Done when: capability status, probe evidence, authorized fallback, and write scope are explicit. Anchors: DBC, DEF, CIRCUIT.

## P2 — Track one bounded repair per GM defect

For observed GM friction or a measured compaction/performance opportunity, preserve a minimal reproduction and an expected improvement. Deduplicate by defect; keep at most one repair owner per defect. When GM repair is within the user's active authorization and the target is reachable, delegate a scoped repair with tests and continue independent project work. Otherwise record the blocked repair and its missing access/authority; do not silently expand this repository's task.

The original requested repair target is the Windows path C:\dev\gm. Confirm the connected Windows node, permissions, actual path, repository identity, and dirty state before touching it. Do not reinterpret it as a WSL relative path or assume /mnt/c is an approved route. If the separately authorized installation lives elsewhere, record the verified host/path and reconcile the repair target before mutation. Never bypass a failed policy/permission check.

Preserve typed fields, provenance, authorization boundaries, error states, and parseability when compacting I/O; less wrapper text is not automatically better. Compare representative before/after fixtures and timing when measuring performance. Run focused regressions, then verify the delivered revision and actual GM capability again. A push alone does not prove a cascading update or a live MCP reload.

Done when: one verified repair is delivered, or a concrete blocked repair with owner/next action is recorded; independent work remains tracked. Anchors: MIKADO, CIRCUIT, ADR, DEF.

## P3 — Compact oversized AGENTS.md without information loss

Trigger on AGENTS.md larger than 30,000 UTF-8 bytes (the documented local interpretation of the ambiguous source “30kb”). Inspect the full file and all task-relevant notes, memories, and available repository commit history within the current access/privacy scope. Report unreadable or unavailable history instead of claiming a complete review. Do not load private memory from another context or machine merely to meet this rule.

Build a traceability table from each still-valid directive/fact to its compact replacement or preserved archive; distinguish active instructions, superseded statements, unresolved claims, and historical evidence. Merge rather than blindly replacing unrelated guidance. Store a recoverable original in authorized version control or an approved archive before applying the compact version; do not expose private memory through a public commit. Obtain explicit approval for any actual deletion of notes/memories not already clearly authorized for this invocation. Keep this source-authoring task non-destructive.

Done when: the compact document fits the chosen budget, retains every verified active directive, has no conflicting active replacements, and has a checked source-to-destination map and recoverable history. Anchors: ADR, FENCE, REFACTOR.

## P4 — Sweep comments by meaning, not by deletion

When comments are encountered in an authorized coding/refactoring task, open one deduplicated project-wide review branch. Delegate it if child capability is available, with explicit file scope and no overlap with active writers. If delegation is unavailable, record the limitation and perform a bounded manual review. Reading the archived user prompt alone does not trigger a sweep of every project.

Classify comments first: redundant narration; design rationale; public API/documentation; legal/license/attribution; generated-code markers; tool/compiler/linter directives; accessibility/localization metadata; examples or fixtures. Convert redundant narration into tested names, structure, or types where genuinely clearer. Retain required legal, generated, public-contract and machine-significant comments in place. Do not damage behavior, accessibility, licensing, or test fixtures to meet a comment-count target.

For rationale that cannot be expressed safely in code, verify it against current source/tests/history. Put concise still-relevant project guidance in AGENTS.md with a source locator; keep detailed context in an ADR referenced there. Preserve local comments when moving them would hide essential context or break consumers. Route proven general GM improvements through P2; speculative ideas remain proposals. Re-run affected tests and inspect the final diff.

Done when: every reviewed comment category has an explicit disposition, behavior is unchanged unless separately requested, required notices remain intact, and transferred rationale remains discoverable. Anchors: REFACTOR, FENCE, ADR, MIKADO.

## P5 — Execute a dependency graph with bounded parallelism

Model outcomes and dependencies before assigning work. Mark nodes ready, running, blocked, validated, or complete; include validation-to-implementation backedges and evidence links. Run independent ready nodes in parallel only when write scopes, external quotas, and available resources permit. Use one owner per writable artifact and one collector/integrator for shared changes. Carry the GM capability status and constraints into each child brief.

Collect actual child results through the supported completion path; do not equate started/running with done. Continue in-scope reviews, fixes, validation, and integration beyond intermediate steps. Stop or pause for a completed requested outcome, cancellation, a concrete unavailable dependency/decision, or an actual resource/permission limit; do not manufacture infinite work or promise an unarranged future continuation.

Done when: each requested outcome has proof or an explicit blocker, no duplicate writer/repair remains active, and required follow-through has an available owner/completion path. Anchors: MIKADO, CIRCUIT, DBC.

## P6 — Preserve truthful attribution

Treat “(insert ur github)” as an unresolved source placeholder, not an identity or permission to impersonate. Inspect authorized repository identity and existing attribution conventions. Use the user's verified intended identity only where accurate; otherwise ask or keep the placeholder explicitly unresolved. Never invent a GitHub account, misstate authorship, rewrite unrelated commit authors, remove required licenses/credits, or claim sole authorship of third-party work. Follow applicable policy for AI/tool disclosure and contribution metadata.

Done when: any new commit/document attribution is truthful, repository conventions and required notices are preserved, and unresolved identity decisions are explicit. Anchors: ADR, FENCE.

## P7 — Author anchor graphs and persist skills

Use [the coding-agent prompt](../../../docs/skills/CODING-AGENT-PROMPT.md) for the graph-only authoring pass. Check the requested Semantic-Anchors reference and primary author/publisher records. Reuse verified existing anchor labels; list missing concepts as LOCAL proposed extensions backed by named, well-known literature and authors. Do not claim to modify the external catalog without separate authorization and actual upstream evidence.

Use only anchor nodes in that pass's nonlinear Mermaid output. Represent branching dependencies, feedback and backreferences as explicitly editorial workflow edges, not invented citations or claims that authors endorse one another. Maintain a separate coverage ledger mapping every added procedure/resource to node IDs. Then convert the graph and coverage into valid SKILL.md files with frontmatter, checkable procedures and direct resource links; graph-only output is not sufficient metadata for a discoverable skill.

Done when: primary reference links and authors are checked, every added procedure is covered by the shared graph, Mermaid parses in a real parser when available, both skill frontmatters validate, and resource links resolve. Report static-only checks honestly if rendering/model execution is unavailable. Anchors: ADR, DBC, HOARE, FALSIFY.
